epub-reader

A browser-based e-book library and reader, built in the shape of dlna-gateway-2.0: Browse · Search · Read. EPUB first, MOBI/AZW3 shortly after, PDF eventually.

Status: M0–M12 complete except M9's provider half. Seven formats, 2,364 books on the shelves, 91% carrying cover art, in daily use over TLS. Next: the names that are clear to a person and not to the code — §12 lists everything open, in the order it is worth doing.

01What this is

Calibre is a library manager with a viewer bolted on. Foliate and Thorium are readers with a file list bolted on. Apple Books is polished but gives you no control over your own metadata.

Calibreexcellentmediocredesktop only

Apple Booksno metadata controlvery goodnative
Thisgoodgoodanything with a browser

The product is the intersection: a reader you enjoy using, on a library you can actually curate, reachable from the couch, the phone, and the desk — the same way dlna-gateway already serves music.

Because the reading engine is a dependency (§3), it is close to commodity. Effort goes into the index, the browse UI, and the metadata, because that is the only part that is ours.

Non-goals

Each is a large product on its own, and none of them is what this is for.

  • Format conversion · e-reader device sync · DRM · news/RSS recipes · EPUB editing
  • No Calibre interaction of any kind — no importing its database, no shelling out to its CLI, no reading its library folders. Everything is built here. (§9, decision 3)

03Reading engine: foliate-js

We do not write a rendering engine. foliate-js (MIT) handles parsing, reflow pagination, TOC, in-book search, and CFI generation and resolution — the genuinely hard part of annotations.

Assessment from reading the source: ~7,100 lines of plain ES modules, no build step, a 374-line README that documents interfaces as contracts rather than as a feature tour. Vendored deps are zip.js (BSD-3), fflate (MIT), pdf.js (Apache) — all permissive.

Three risks, each of which becomes a rule:

It declares itself unstable

version: 0.0.0, no npm release, and the README says outright to expect the API to change at any time.

Rule

Exactly one file imports foliate-js — static/reader.js, exposing our own open / goTo / position / annotate / search. Upstream churn lands in one file. Pin it as a submodule and update deliberately.

Bus factor of one

268 of ~290 commits come from a single maintainer, with bursty cadence — active months separated by quiet ones. MIT plus 7k readable lines makes forking a genuine fallback rather than a theoretical one.

Scripted content is a real hole

EPUBs can contain JavaScript, and the README is blunt that iframe sandboxing cannot contain it: content is served same-origin via blob: URLs, and a long-standing WebKit bug forces allow-scripts.

Rule

A CSP blocking all non-self scripts ships from day one, set as a response header in FastAPI. This is not a later hardening pass. Test against johnfactotum/epub-test.

3.1  What M0 established

Pinned at 78914ae (2026-05-01) as a submodule at static/vendor/foliate-js.

  • It renders. EPUB parsing, pagination, TOC and metadata all work under the strict CSP, unmodified. view.js disables zip.js web workers itself, so no worker-src relaxation is needed.
  • CSP genuinely contains EPUB scripts. A hostile fixture carrying both an inline and an external script is rendered; neither runs. Verified negatively — weakening script-src to allow 'unsafe-inline' blob: makes the test fail, so it is not passing vacuously.
  • foliate-view attaches a CLOSED shadow root. CSS selectors cannot pierce it, so frameLocator('foliate-view iframe') never matches. Book sections must be reached through page.frames() by their blob: URL.
  • Fonts. dlna-gateway loads Syne + DM Mono from Google Fonts. This app uses a system stack so the CSP needs no external origins at all. Self-hosting those two faces was flagged for M1 and was not done — it carries to M2.

Known upstream weak spots we design around rather than discover: the paginator uses CSS multi-column (epub.js's strategy, and inherits its slowness and CSS quirks), in-book search is slow enough to need incremental loading, and the PDF adapter is self-described as a proof-of-concept. Upstream tests cover CFI parsing only, and there are no types.

Books nobody can open

50 books in the library are Apple Books purchases, encrypted with FairPlay: every document inside is ciphertext and the key lives in an Apple ID. They are excluded at scan time rather than listed as titles that fail.

Encrypted fonts are not DRM

META-INF/encryption.xml is also how fonts are obfuscated, which is ordinary and readable — 8 books here do it, the Earthsea novels among them. The difference is what is encrypted: documents mean DRM, fonts mean typography. Excluding on the presence of the file alone would have lost 8 books that work perfectly.

A locked book is not a failure — nothing is wrong with the file or with us — so it is counted separately: 50 locked by their shop. It is recognised before the book is hashed or stored, or every scan would hash fifty books it is about to throw away.

Two references to a book row have no cascade, and both took a scan down in turn once books started being deleted: book.duplicate_of, where a hidden copy points at the copy that was kept, and author_work.book_id, where "Also published" links a work to the copy you own. Neither should vanish with the book.

Scope: six formats, and one refusal

EPUB, MOBI, AZW3, PRC, PDF and CBZ — plus EPUBs that were never zipped, which are directories rather than files. Only CBR stays out: it is RAR, and nothing in the stack reads RAR. Listing a format we cannot render only promises what we do not deliver.

BookLibrary.SUFFIXES is still the single switch, and resolve() still refuses anything outside it. Three rendering models sit behind those six extensions: reflowed text (EPUB, MOBI and friends), rasterised pages (PDF, via pdf.js), and images page by page (CBZ) — so the typography controls apply to the first and not the other two.

Two upstream workarounds — both in static/reader.js

1. render() before a document exists. A ResizeObserver calls render() → columnize(), which dereferences this.document.documentElement unguarded; a resize landing while a section loads throws and abandons the layout.

2. %2C in contents hrefs. Calibre writes the NCX href percent-encoded while the manifest keeps the literal comma, and resolveHref() uses decodeURI(), which by design never decodes reserved characters. This broke the contents on ~22% of the real library. Fixed by resolving first, then retrying with reserved characters decoded — warnings fell from 18-in-80 to 1-in-50.

4.2  Reader

Full viewport, paginated by default. Click zones left and right, arrow keys, swipe on touch. Chrome fades while reading and returns on tap.

Controls: font family and size, line height, margin width, column count, theme (light / sepia / dark / black), and paginated vs scrolled. The paginator exposes all of these as element attributes, so they are cheap. Position is written back as a CFI on every relocate, debounced. Selecting text offers highlight, note, copy, and search-in-book.

4.2b  Choosing a book is not opening it

The centre pane shows either the book's details or the reader. Choosing a book shows it; reading starts when you press Read. Navigation is a hierarchy — library → book → reading — and back retraces it one level at a time rather than dumping you at the library from the middle of a chapter.

Empty panels say what is missing rather than showing nothing: "Nothing about Stephen R. Donaldson has been looked up yet." Until enrichment runs, Also published lists the rest of that author's books in your own library, grouped by series and numbered.

4.3  Reading on a phone or an iPad

Three columns on a touch screen leaves the reading pane a couple of hundred points wide, and the paginator has nothing to lay out into — the book showed nothing at all on iOS. Choosing a book gives the reader the whole screen, with a back arrow to the library.

Touch details that are easy to get wrong: height: 100dvh, because 100% of a viewport that moves as Safari's toolbars slide is not a height; a 44 pt tap target inside env(safe-area-inset-*); the search box gives way to the book while reading; and the title is clamped to one line, having wrapped to three and pushed the header from 33 pt to ~90.

4.4  While a book loads

The book's own cover, turning, above a bar and a label — confined to the reading pane so the library stays usable. Two phases, because only one can be measured honestly:

  • downloading — a real percentage, from Content-Length against bytes read off the stream. The app fetches the book itself so the bytes can be counted, then hands foliate a File (not a Blob: it sniffs format partly by file.name).
  • preparing — foliate exposes no progress while parsing and laying out, and a 1.2 MB single-section book spends 6–8 s there. The bar goes indeterminate and the label says so, rather than inventing a number that would be wrong.
A second WebKit lesson

WebKit will not paint an <img> inside a transform-style: preserve-3d context. The cover rendered as a flat navy rectangle in Safari while Chromium was perfect, from identical markup. A wrapper element did not help and removing backface-visibility did not help — only dropping preserve-3d did. The book now turns within ±58° on perspective alone, which needs no back face and keeps the cover visible throughout.

4.5  Highlights and notes

Selecting text offers Highlight · Note · Copy and a row of colours; the right panel gains a Highlights tab beside Contents and Display. Marks are server-side and shared, exactly like reading position (decision 7): a passage marked on the iPad is marked on the Mac. What stays per device is how the page looks, not what is on it.

Rule

static/reader.js is still the only importer of foliate-js. It answers foliate's draw-annotation event by saying what a mark should look like — the engine asks rather than decides, so the palette lives in one place and matches the set the server will accept.

Three things the shape of the DOM forced:

  • The offer belongs to the page, not the book. A document cannot draw outside itself, so a selection's rectangle is converted from frame coordinates to page ones. The menu sits above the words unless there is no room — a menu covering the words you just chose is no use.
  • Selection is watched per section, because foliate replaces the document when you move between them.
  • A section gets a fresh overlay when it loads, so everything drawn on it is drawn again.
Emptying a note is not the same as not mentioning one

PATCH applies only the fields a request actually names: {"note": null} clears it, {} changes nothing. Without that distinction a colour change would quietly erase a note, since both arrive as None. Anything outside note and color is refused rather than ignored — the words and the place are what a highlight is, and editing them would make it a different highlight wearing the same id.

The note is asked for before the mark is made, so a cancelled note leaves no orphan highlight. It is a composer rather than window.prompt, which blocks the page, cannot be styled, and on iOS reads as the browser asking rather than the app.

4.6  Shelving without opening the book

Putting a book on a shelf used to mean opening it first — the only way in was the reader's ＋ Shelf button. But shelving is something you do while browsing: you recognise a book in the list and file it. So every row carries ＋, which opens the same sheet the reader uses — the same sheet, not a second one, since two ways to edit one thing is how they end up disagreeing. Looking at a shelf adds −, which takes the book off that shelf.

  • A button cannot live inside a button. The row has been a <button> since M2, so the controls sit beside it in a .book-item wrapper, and every existing test that clicks .book-row still means what it did.
  • Always visible, 44 pt on touch. Hover is unreachable on an iPad, which is where most of this library is read.
  • Only a stored shelf offers −. "Reading now" is a consequence of reading rather than a list.

4.7  Finishing a book, and leaving a shelf

That left three things you still could not do: say you had finished a book, throw a shelf away, or get a book off Reading now — where anything opened once stayed for ever.

You cannot take a book off a consequence; you change the fact

A smart shelf is a view of reading state, so the row controls there edit the state and the shelf follows: ✓ marks a book read and it moves to Finished, − says you are not reading it any more. There is still no route that puts a book on a smart shelf — the asymmetry is the design, not an omission.

Marking a book read keeps your place: finishing is not forgetting, so the CFI, the fraction and the highlights stay and only the status changes. The same gesture sits on the book detail as a toggle rather than a one-way door — a book marked read by mistake, or picked up again, has to be able to say so — and it is the only way to mark a book you never opened here, which is most of what a thirty-year library contains.

Deleting a shelf asks twice. One tap turns − into Delete?, the second does it, and an unanswered question goes back to being an offer after five seconds. A shelf cannot be un-deleted, and a stray tap on a phone should not cost you a list you built. The books stay: a shelf is a grouping, not an owner.

Naming a shelf is the app asking, not the browser. NameComposer generalises the note composer above — Enter keeps the name, Escape or tapping away gives up, and an empty name is giving up rather than a shelf called "". A shelf made from the sheet while holding a book is a shelf meant for that book, so it is created and chosen in one gesture.

A bug this uncovered: ＋ New shelf was hidden on some render paths and not others, so leaving Shelves for Titles left the button behind — offering to make a shelf on a screen with no shelves on it. Its visibility is decided once now, on every path.

05Data model

Two decisions carry the design.

Files stay where they are

We index in place, so identity is the content hash, not the path — moving or renaming a file updates a row instead of creating a duplicate. We never move, rename, or write to your book files.

Metadata carries field-level provenance

book_meta in dlna-gateway already gestures at this with its source / fetched_at columns. This is the full version:

Rule

Every field records where its value came from — file, provider, user — and whether it is locked. Enrichment may overwrite a field only if its origin is file and it is unlocked. A user value is never overwritten automatically.

That is what makes re-running enrichment across the whole library safe rather than a gamble.

6.1  Genre vocabulary — BISAC subset

Providers return BISAC codes, free-text categories, and folksonomy tags interchangeably. We normalize onto a fixed ~40-term subset of BISAC subject headings, stored in genres.tsv in the repo and loaded into the genre table at startup.

  • Each row is bisac_code + display name — FIC028000 → Science Fiction, FIC022000 → Mystery & Detective, FIC009000 → Fantasy
  • Take BISAC's major sections and one level of subcategory, no deeper — FICTION / Science Fiction, not FICTION / Science Fiction / Space Opera. Deeper is unbrowsable at library scale
  • genre_map.tsv maps provider strings ("Science fiction", "sf", "Sci-Fi & Fantasy") to codes. Unmapped strings are logged, not guessed, so the map grows from real data
  • Raw provider strings are also kept as free tags, so nothing is lost

Without this the Genres browse mode is unusable.

6.2  "Also published" — novels and novellas only

Open Library's works list is long and noisy: anthologies, omnibus editions, single short stories, forewords, and non-fiction all appear alongside the novels. The default view is work_type IN ('novel','novella').

Classification is heuristic and will not be perfect, so it is transparent about that:

  • Title patterns exclude collections — Complete Works, Collected Stories, Selected …, … Omnibus, … and Other Stories, The … Trilogy
  • Open Library subjects and Google Books categories flag non-fiction
  • Page count, where known, separates novella from novel
  • Anything unclassified stays unknown — hidden by default, shown under show all, never silently dropped

The filter is a display filter. Every fetched work is stored, so reclassification never needs a re-fetch.

Rule

Merging authors is destructive, so the bar is high. A group merges only when the names are identical once spacing and punctuation are removed, when Open Library resolves both to the same author, when one spelling is unknown to Open Library beside a near-identical one it knows well — the signature of a typo — or when everything the other name is credited with is in the keeper's bibliography. Anything refused is reported, never silently dropped.

What the rules refuse is reported, and POST /api/authors/merge is how a reader who knows better overrides them — which is what settled Anne Rice / Ann Rice, Arthur Clarke / Arthur C. Clarke and the four spellings of L. E. Modesitt Jr.. Open Library holds two records for each of the first two and none of their books overlap here, so nothing could have proved it. A hand merge records provenance like any other correction.

The bibliography rule is the strongest of the four, because it asks what the books are rather than how the name is spelled — and it is the only one that settled the three Donaldsons. Open Library holds a second record for "Stephen Donaldson", 38 works beside the canonical 126, and Stephan Donaldson scores 0.87, just under the typo bar. But all four of their books are Thomas Covenant novels, every one in the keeper's works list. A single shared title would prove nothing — two writers can name a book the same — so it asks for all of them.

The typo rule is what separates Issac Asimov from Isaac Asimov while leaving Stephen King and Stephen Hawking alone — both of those are real people, and the provider knows both. Five look-alike groups remain reported and unmerged, including Anne Rice / Ann Rice and Arthur Clarke / Arthur C. Clarke, where Open Library itself holds two records.

The spelling that survives is not the one with the most books — that kept DIANE CAREY over Diane Carey, and Raymond E Feist over Raymond E. Feist. Open Library supplies it instead, but only when its answer is the same name and better formed: it holds J.k. Rowling, which is an improvement on nothing.

A bare title is weak evidence

Looking up "Second Chance" returned a book James Patterson did not write. Where the filename names its author — Cussler, Clive - Dirk Pitt 01 - Pacific Vortex — that name arbitrates, and a candidate contradicting it is refused. The same rule catches an author holding a fragment of the title: Jack And Jill was split on the "and" and both halves became people.

Titles come from the author's bibliography, not from a title search. Once the author is settled the only question left is which of their books this is, and the candidate set shrinks from millions to a few hundred. Two guards earn their keep:

  • Open Library caps a bibliography at 200 works, so Asimov's list holds Foundation but not Foundation and Empire. A contained work must account for most of the title, or the one quietly becomes the other.
  • But a work that ends the title should win, because a filename puts the shelf first and the book last — without that, five different Snicket books became A Series of Unfortunate Events, the series being a work too, and a longer one. What settles the two rules is what the leftover words are: another work, a number and an article is scaffolding; forward in Forward the Foundation is part of the title. Scaffolding must carry a number, or Storm Warning Storm Rising resolves to the second of the two books it names.
  • A colon after a number separates the shelf from the book. Cleaning drops what follows a colon as a subtitle — right for On Writing Well: An Informal Guide, catastrophic for The Belgariad 1: Pawn of Prophecy, which leaves belgariad 1 and matches the series omnibus. On the real library that turned five Eddings novels into The Belgariad, four Shiloh Walkers into The Hunters and three Anne Rices into Vampire Chronicles.
  • A provider's title is not always a title. Kiss the Girls: A gripping detective thriller in the Sunday Times bestselling series (Alex Cross 2) is a blurb with a book's name in front of it, so a trailing bracket goes, and a correction may tidy a title but never invent a subtitle the file did not have. Editions and translations list one work several times; those collapse to one, keeping the article — A Falcon Flies and Falcon Flies are one book.
  • A leading series number comes off without asking anybody — 01 Lord Foul's Bane, 11.Scion of Cyador — except when the number is the title. 10 is Better Than 01 and 50 Philosophy Ideas You Really Need to Know are real books; zero-padding is what tells them apart.

The title the file gave is kept in metadata.file_title, so every rename is reversible — which is how twelve bad ones were undone rather than argued about. Two that no rule can reach, because the filename hides the book in the middle (Anne Rice - Memnoch The Devil - Vampire Chronicles #5), are set by hand and locked: origin = 'user' means no pass touches them again.

Reviewing the result matters as much as the rules

Sampling thirty of 251 changes found the marketing subtitles. The collapses only surfaced by asking a different question — which corrected titles have become identical to a sibling's? Sixteen groups now share a title, and all of the remaining ones are genuine: they are duplicate copies of a book, which is a useful thing to have learned about the library.

6.4  The file is the first word, not the last

Corrections have to survive a rescan, and until this was found they did not: _write_metadata overwrote every column and ran DELETE FROM book_author unconditionally, so replacing a book file put its wrong author straight back.

Rule

The indexer reads field_provenance first and takes from the file only what the file still owns — the same rule enrichment follows. Every repair pass records provenance for what it changed, or the next scan would undo it.

A routine scan short-circuits on unchanged size and mtime, so this only ever bit when a file was touched, edited, or replaced with a better copy — which is exactly what a growing library does.

6.8  The status line counts what is on the shelves

/api/status reported 590 authors while the Browse tab listed 395, and both numbers were honest: a repair leaves an author row behind rather than deleting one another book might still use, and genres.tsv is loaded whole at startup whether a book uses a term or not. Counting rows counts things nobody can see.

Rule

The status counts join through to a present book, exactly as the browse lists do. A status line that disagrees with the screen below it is wrong, however defensible each number is on its own.

6.6  Running the passes as the library grows

New books arrive with the same defects the first 1,300 had, so the passes are a command too:

./run.sh repair            # check authors and titles, change nothing
./run.sh repair --apply    # ...and fix what it can prove

They run in dependency order — authors → books → titles — because everything else is asked of an author. Setting REPAIR_ON_SCAN=true makes run.sh start|restart do it after the scan, so dropping books in and restarting is the whole workflow. Off by default: reaching a provider is not something to do on someone's behalf without being asked.

Rule

A restart must not become 1,200 requests. Everything a provider says is written down — the works list into author_work, the attempt itself into author.fetched_at, which is stamped even when Open Library has never heard of the author. Both are checked before asking, so an author is looked up once, ever, and every later run reads our own tables.

6.7  Keeping author data fresh: oldest first, ten a week

A bibliography is not static — living authors publish — so author data needs re-asking about once a year. The obvious schedule is a letter of the alphabet every fortnight, which covers 26 letters in a year.

Why not the alphabet

Surnames are not evenly spread. This library has 49 authors under S and one under U, several letters with none at all, and a few sort names starting with a digit. One fortnight would make 147 requests and the next three, while the S authors waited a year regardless of what they published.

Sorting by when we last asked balances itself, needs no calendar, and picks up wherever it left off when a week is missed. com.example.epub-reader.refresh.plist runs it every Sunday at 04:12 — not on the hour and not at midnight, where every other cron job lives. Ten authors is thirty requests, some fifteen seconds of traffic, and a full round of 395 authors in about forty weeks.

6.9  Books that were never zipped

265 books in the library are directories rather than files — iTunes exports, and anything somebody unzipped and never put back. They had been invisible since M2, because the scan listed files only: 265 books you own and cannot see.

They are indexed in place and zipped on the way out, mimetype first and uncompressed as the container spec asks, so the reader, CFI positions, highlights and the loading bar carry on knowing nothing about it. Serving the tree file by file for foliate's directory loader would have put a second book-fetching path through the CSP and the position code for no gain.

  • The walk stops at a book. A directory named *.epub holding a META-INF/container.xml is one — and without both tests, either Drive.epub/ becomes a hundred documents or somebody's Notes.epub/ folder becomes a book.
  • A directory's own mtime does not move when a file inside it is edited, so an unpacked book is stamped by the size and mtime of its contents — otherwise every scan would call an edited book unchanged.
  • The hash covers names as well as bytes, so moving a file within a book changes its identity as editing one does.
  • The parser reads a loader, not a zip. ZipContents and FolderContents both answer names() and read(), and a book cannot name a file outside itself.

6.11  Series, read from the filenames

135 books of 2,323 had a series, every one from a calibre:series tag inside the file. §6 said series would come from providers; that was never built, so most of the library had no thread between its books — the Dune novels sat beside each other as strangers.

The filenames know, and need no provider: 297 books filed under 80 series, from the shape Cussler, Clive - Dirk Pitt 01 - Pacific Vortex. The library holds 154 series now, from 39 before M8.

A series of one is a misread

"10 is Better Than 01 - Heather Jarman" is a book called "10 is Better Than 01", not book 1 of a series called "is Better Than". A name is only believed when two books by the same author agree on it, which threw out every false positive the real library produced. An author's own name is refused too, and a four-digit number is a year rather than a position.

Then series found duplicates that titles could not. Filing revealed 46 positions claimed by two books — Enders Game 4 - Children of the Mind.epub beside the same file with the author appended, their stored titles differing just enough to look like two works. One author cannot have two fourth books in one series.

What it cannot reach: Chapterhouse Dune and Children Of Dune carry no marker, so Frank Herbert's own novels are still loose. Brian Herbert's are filed — Dune Chronicles, Prelude to Dune, Great Schools of Dune, Heroes of Dune — because those files were named by someone who cared.

6.11a  Saying it yourself

Three books stayed wrong after every automatic pass, each in a way no rule could reach: The Light of All That Falls is book three of the Licanius Trilogy, its file says nothing, and its filename carries no number. So PUT /api/books/{id}/series joins PUT /api/books/{id}/authors — and, like it, what you say is origin = 'user', locked, and never touched again by a scan or by any pass.

That is the whole of hand-editing today: who wrote it, and where it sits in a series. Title, synopsis and genres remain provider-or-file only; title is deliberately outside even the enrichment writable set, because the file's title is what you see in your own folders.

A subtitle is part of the title when you are telling two books apart

normalise_title strips everything after a colon — right for asking a provider, catastrophic for comparing: it made Dune: House Harkonnen into Dune, and since both authors are "Herbert", Frank Herbert's novel was hidden behind Brian Herbert's. Dedupe now compares on a title that keeps its subtitle, and auditing all 289 hidden copies afterwards found 16 wrongly hidden books of the same shape and restored them.

A wrong position hides a book as surely as a wrong title

With that fixed, dedupe still wanted to hide Interview with the Vampire behind The Vampire Lestat. It was right that two books cannot both be Vampire Chronicles #1 — the file was wrong: Lestat's own OPF carries calibre:series_index = 1. The rule found a real fault and blamed the wrong book, which is exactly what hand-filing is for.

Filed by hand so far: the Licanius Trilogy 1–3, the six original Dune novels plus Anderson's two, the first two Vampire Chronicles, and — added 19 August 2026 — Geodyssey #1 (Isle of Women, whose filename misspells the series, so nothing could corroborate it) and Bio of a Space Tyrant 1–4 and 6.

A series can be split by two filing conventions

The four EPUBs named their series Tyrant; the PDF was hand-filed as Bio of a Space Tyrant. Both names are honest, and nothing automatic chooses between a shorthand and the published one. The full name wins because that is what the books are called, and the shorthand's series row is left behind rather than deleted — every listing joins through to a present book, so an empty series cannot show. #5 is genuinely missing rather than misfiled: Statesman is not in the library, which is the gap-finder working.

6.11b  Three facts written as one name

Anthony, Piers - Xanth 08 - Crewel Lye browsed as a single run-on title, credited to nobody — or to harry, which is whoever ran the scanner. 45 of Piers Anthony's PDFs looked like that, and the cause was one missing step rather than three.

§8.4 made the filename lead for PDFs, but only for the title: epub_pdf reads the author from the Info dictionary alone, so 35 of the 45 had no author at all. §6.6 runs its passes authors → books → titles because everything else is asked of an author — and SeriesFromNames says so in as many words, refusing a name when there is nobody to agree with. The Xanth novels could never have become a series either. The first domino had never fallen.

A file that named itself is not this pass's business

It acts only where the title the database holds is the filename, which is the mark of a file that said nothing. An EPUB whose OPF gives a real title is left alone even when its filename would parse — Anthony, Piers - Cluster 2 - Chaining The Lady.epub already knows it is Chaining the Lady.

The author leads, or nothing happens

Surname, First - … at the head is the shape this library uses, and the comma is what makes it a name rather than two words that happen to lead. A filename with its author at the end — 10 is Better Than 01 - Heather Jarman — is a book called that, and is refused.

The series is not judged here

SeriesFromNames already decides that, and its rule — two books by one author must agree — is what keeps "is Better Than" out of the library. This pass credits the author first so that rule can finally run, then asks it, then reads the title in the light of its answer. Two implementations of one judgement is how they come to disagree.

Measured: 45 books credited, 17 filed under six series, 45 retitled — Xanth, Mode, Aton, ChroMagic, Jason Striker and Geodyssey. Every one of the 45 was then read, and the audit found two faults, both in rules that already existed.

A book already on the shelf is corroboration too

SeriesFromNames counted agreement only among unfiled books. Geodyssey 02 and 04 had been filed by an earlier run, so when 03 arrived it was the only unfiled book claiming the name and was refused as a series of one — with two of its own siblings already filed under it. Agreement is about the library, not about this run.

A title this pass wrote is still its own to refine

Hope of Earth then got its series and kept its run-on title, because it no longer looked like a filename and so fell out of the pass's own scope. A book alone on its shelf keeps its number; when a sibling turns up, that number becomes the shelf talking. The same run reported nothing to read while filing a book, because the summary described only the first of its three steps.

Two books nothing could corroborate were filed by hand, which is what PUT /api/books/{id}/series is for: Geodessey 01 - Isle of Women is a misspelling of Geodyssey, so that spelling had one book and nothing to agree with it, and Bio of a Space Tyrant 06 is the only book of its series in the library. All 45 now read as three facts, 24 of them in seven series.

A person's word settles the shelf, however the file spells it

Hand-filing left Isle of Women still titled Geodessey 01 - Isle of Women — the shelf talking twice and disagreeing with itself — because the trim demanded that the filename spell the series the way the library does. It cannot: the misspelling is precisely why nothing corroborated it and why a person had to file it at all. The number is what ties the words to the shelf, so it must agree; a filename saying 01 under a book filed at #4 keeps its words.

"The title IS the filename" was only ever a proxy

The guard means "the file said nothing about itself". Four Bio of a Space Tyrant EPUBs carry Anthony, Piers - Tyrant 1 - Refugee in their own OPF while the file on disk has the author appended a second time, so the two were not equal and the pass walked past them. The file did speak; what it said was a filename. The tidier of the two names wins — reading the file instead would have left "Refugee - Anthony, Piers".

A title never ends in .txt

12 books here do — Volk.doc, Running with the Demon.txt, Nanny Ogg's Cookbook.htm — the mark of a library converted from one format to another by somebody who kept the old name. A closed list of known extensions, so Mr. Norrell is safe.

Across all of one author's formats that took 7 more titles, filed the four Tyrant novels 1–4, and gave Currant Events its Xanth #28 — the last only because agreement now counts books already on the shelf. And it split a series: the four EPUBs are filed under Tyrant from their filenames while the PDF hand-filed earlier sits under Bio of a Space Tyrant. Both names are honest and they are one series; nothing automatic chooses between a shorthand and a full name.

241 more books across 49 authors — 235 PDFs and 6 PRCs — carry the same shape and are not done, because a pass this sharp should be aimed rather than loosed: ./run.sh names --author "Piers Anthony" --format pdf --apply. A scope narrows which books are read, never how they are judged.

6.11c  A co-author written into the title

§12's tier 0, and it needs nothing but a rule — no provider, no key, no network. Dead Morn (with Roberto Fuentes) is a book by two people whose filename had room for one, so the second went in brackets and every pass since read it as part of the book's name.

Measured over the whole library rather than the two examples that prompted it: 13 books carry it — nine of Piers Anthony's, two of P. N. Elrod's, one each from Robert Asprin and Andre Norton. Every other parenthetical is the scanner talking ((not ocr), (v2.1), (txt), (9781982156176), (1946)), and the word with is what tells them apart.

A co-author is a second author, so there must be a first

Two P. N. Elrod PDFs credit nobody, because their filenames name him and epub_pdf reads only the Info dictionary. Crediting Nigel Bennett alone would promote the collaborator to author, which is worse than the bracket. They are left for ./run.sh names.

Only the with bracket goes

Elvenblood (With Mercedes Lackey) (v1.0) keeps its version tag — somebody else's rubbish to clear, and a pass that tidies more than it was asked to is one nobody can predict.

Measured: 11 titles freed, 12 people credited, 2 deferred.

ORDER BY belongs inside the aggregate

This uncovered a bug present since M2. §5 says credit order matters, which is why book_author carries a position — and the browse query asked for it and did not get it. Outside the aggregate, ORDER BY orders the single row the aggregate returns, which is no order at all: GROUP_CONCAT kept whatever the join handed it, in author_id order, so Mercedes Lackey came out ahead of Andre Norton on her own collaboration — she was already in this library, and her row is older than his. Invisible for as long as almost every book had one author.

The first version of the test passed against the broken query: a fixture that creates authors in credit order cannot fail. It only became a test once it built the collaborator first, so her id is lower — the actual library, and the only shape that fails.

6.11d  A title that was cut off, finished by a provider

§12's tier 1. Anthony, Piers - The Caterpillars Questi.pdf was truncated years ago by somebody's filesystem, and no amount of matching fixes a fragment: Open Library holds The Caterpillar's Question, and The Caterpillars Questi matches nothing at all, for ever. The damage is always at the end, so trimming back to the last complete word turns a dead query live.

There is no clever damage detector, and there should not be

A word cut mid-syllable cannot be told from an invented one without a dictionary, and this library is full of Xanth, Chthon and Phthor. So the provider is the detector: ask about the title as it stands, and only if nothing comes back is there anything to repair. One request per book — which is why the pass takes a scope.

The answer must COMPLETE our fragment, word for word

Everything before our last word must match exactly, and our last word must be the beginning of theirs. A rule that can only ever lengthen a name cannot quietly swap in a different book.

A fragment needs a whole word beside it

With one word there is nothing holding the answer to the book: The Ring would cheerfully become The Rings of Saturn, a different book by a different author.

Two guards the real answers forced: an apostrophe joins rather than separates — the catalogue's caterpillar's and the filename's caterpillars are one word, and splitting on it made three words against two — and Open Library answered "The Bamboo Bloodbath (#3 in the violent new series featuring Jason Striker, Master of Martial Arts)", so TitlePolish takes the marketing off before anything is written.

Every question and every answer is cached in provider_query. §6.6 made an author "asked once, ever" by stamping author.fetched_at, but that records asking about a person and this asks about a string. A silence is an answer and is kept like any other: 122 questions, 98 answered, 24 silences, and the second run asked nothing.

Measured: 1 title finished, and the other refused — correctly. Bamboo Bloodbath & Ninj names two novels and Open Library holds one of them, so their answer is shorter than what we hold. The cache shows exactly that: the trimmed question found The Bamboo Bloodbath and the rule threw it away. Completing a fragment is not replacing it with half of itself.

6.11e  What the scanner wrote into the title

Blue Moon (v2.2), Enemies of the Roman Order (not ocr), Myth-Nomers (uc). A version stamp, a note that a scan never went through OCR, a bare format — none of these is part of a book's name. 17 titles carried one, and they are exactly what the library-wide names run left behind, deliberately: that pass tidies what it was asked to and no more.

A closed vocabulary, never "strip any bracket"

The same 66 bracketed titles hold (The Murderbot Diaries), (Osprey, Men at Arms #121), (PhD, 1998) and (Mysterious Creatures) — every one part of the book or of its shelf. Guessing would cost more than it cleared. Known values only, the rule §6.1 follows for genres.

Two shapes the real titles forced: two brackets with no space between them, Rome and Her Enemies (Osprey)(not ocr), where only the scanner's may go; and a title is never emptied — a book called (v1.0) is absurd, but a book called nothing falls out of every list that sorts by title. Measured: 18 cleaned, then 6 more once underscores were added.

Underscores stand in for spaces, where they have replaced them

Hamilton,_Laurell_K._-_Anita_Blake_04_-_The_Lunatic_Cafe is an ordinary name from a filesystem that never learned about spaces, and read as it stands it parses as nothing — so that book kept a scanner called "Lee Hughes" as its author and its whole filename as its title. Put back, it is The Lunatic Cafe · Laurell K. Hamilton · Anita Blake #4. Only where they outnumber the spaces: one underscore among real words is punctuation, and Chthon_Phthor Omnibus keeps it.

A pass must read the same source on every run

CreditsFromNames took its facts from the stored title when that looked like a filename, and from the path otherwise. Once the pass has written a title, though, the title is a real title — so a second run fell through to the path, and Roberts, Nora - A World Apart - Emily & Jane.epub is longer than the file's own name, a scanner having signed it. A World Apart became A World Apart - Emily & Jane, and would have grown again. file_title is what the file said and does not change between runs. 35 books had drifted; re-running with the fix restored every one, because the original was still in file_title — the whole reason it is kept.

Two passes can undo each other for ever

tags took (v2.1) off a title; names derived that title afresh from file_title, which is the file's own words, tags and all, and put it straight back. A title names writes now goes through this rule on the way out, and the pair settle.

Passing the first time is not the same as passing

These tests were written before the module but not run before it, so the remedy the CSP test established applied here too: the rule was temporarily disabled and 12 of the 23 failed. That is what makes the other 11 worth having.

A bug this found in run.sh: the usage block was sed -n '3,38p', a fixed line range, so every command added pushed the last one off the end — fragments fell out of the help the moment tags was added, silently. It now reads to the closing rule rather than to a number somebody has to remember, and a test asserts that every command appears.

6.12  Comics

A CBZ is a zip of images and nothing else: 286 indexed, and only one in 120 carries a ComicInfo.xml. So the filename is the metadata, and these filenames are full of the scanner's notes:

Everything in brackets is the scanner talking, and the year among it is the edition — a 2025 scan of a 1985 comic is not a 1985 work. 6.11i  No authentication, and the two things that follow from it

This is a personal service for one household, reached over a tailnet. It has no authentication and nothing here uses cookies — a decision rather than an omission. But two consequences of it were being left to luck.

A service with no authentication acts for whoever can reach the port

EPUB_BIND now defaults to 127.0.0.1 rather than 0.0.0.0. Widening it is a deliberate edit onto a network you trust, with the reason written beside the setting. The old default meant that copying .env.example and filling in LIBRARY_ROOT — the whole setup, as the README describes it — published the library to the LAN.

CORS withholds the reply, never the act

A cross-site request here cannot be authenticated, there being nothing to authenticate — and it does not need to be. POST /api/books/forget-missing?apply=true&force=true drops reading positions and highlights. A bodiless POST is a CORS "simple request": sent with no preflight, with the same-origin policy hiding only the response from the calling page. The request still arrives and is still acted on, so any site open in a browser on the same machine could have driven every maintenance endpoint.

SameOriginPolicy refuses a state-changing method whose Origin is not ours. Reading is never refused — a GET changes nothing, and the same-origin policy already stops a foreign page reading the answer. No Origin at all is allowed: curl, run.sh and the test suite send none, and a browser always sends one on these methods, so absence is a non-browser caller rather than the case being defended against. Origin: null is refused along with everything else that is not us — a sandboxed frame splits to an empty netloc and matches no host. It is registered inside the headers middleware, Starlette running the last-added outermost, so a 403 still carries the security headers every other response does.

6.11h  A shelf label is not a name, and dedupe found out

Running dedupe proposed nine works, and the ninth would have hidden a book: The Serpent's Shadow behind The Gates of Sleep, both Mercedes Lackey's Elemental Masters and both real novels. Two faults, one on top of the other, and the first was ours.

A name that gives only a shelf and a number is not a name

One EPUB calls itself Lackey, Mercedes - Elemental Masters 02 in its own OPF — a series, a position, no book — while the file on disk is … - The Gates Of Sleep.epub. §6.11g had made file_title the source because it does not change between runs, which is right; preferring it blindly took a shelf label as a title. The three names for a book are now tried in order of trust, skipping any that names no book. Eight titles came right, among them Violets Are Blue (from Alex Cross 07).

A wrong position hides a book as surely as a wrong title

Dedupe never looked at the title: its key is (series, index, author), both files claim 02, and one author cannot have two second books. The rule found a real fault and could only blame the wrong book. The Serpent's Shadow is Elemental Masters #1; filed by hand, and the ninth group disappeared.

Applied: 8 spare copies hidden of 8 works — two Farseer novels and a Nora Roberts filed twice, and five books held as both an EPUB and a PDF, where the EPUB is the book and the PDF a picture of one. No file was deleted. The library: 2,364 books on the shelves, 288 hidden, 577 authors, 235 series — of 2,374 indexed, the ten refused comics counted as failed rather than shown.

6.11g  A book dropped in is a book filed

§6.6 said dropping books into LIBRARY_ROOT and restarting was the whole workflow. It was half true: REPAIR_ON_SCAN runs the three passes that ask Open Library and is off by default for exactly that reason — while everything built since is local, free, and ran on nothing at all. A book added yesterday browsed as Anthony, Piers - Xanth 12 - Man From Mundania, credited to nobody, exactly as the first forty-five did.

What costs nothing may be done for you; what costs a request may not

TIDY_ON_SCAN is on unless turned off: these passes read names, write to our own database, reach no provider, and keep what the file said in file_title, so nothing they do is one-way. REPAIR_ON_SCAN and fragments stay opt-in.

They run in §6.6's order — authors, then what is asked of an author, then what depends on nobody: names, coauthors, tags. Both ./run.sh scan and the server's own startup scan do it, so a launchd start behaves exactly like ./run.sh restart. Proved on the real library: a PDF dropped in as Anthony, Piers - Xanth 12 - Man From Mundania (with Nobody Real).pdf, carrying harry as its author, came back after one restart as Man From Mundania · Piers Anthony, Nobody Real · Xanth #12.

A title a provider confirmed outranks one read off a filename

§6.11d had repaired The Caterpillars Questi to The Caterpillar's Question; the next scan read the broken name again and put the fragment back, whereupon coauthors saw the bracket it had just restored and rewrote the title a second time. Within provider, openlibrary is what a catalogue asserts and filename is what we inferred — so the derived one yields.

Passes must settle, not take turns

names derives a title from file_title, the file's own words with the co-author bracket and all; coauthors takes the bracket off. Every restart put "(with Roberto Fuentes)" back and took it off again — 13 books retitled and 13 co-authors "freed" on a scan where nothing had changed. Both read the same source now and each writes only the facts it owns. The idempotence test that existed used a book with no co-author, which is why it never saw this.

6.12a  Comics packed with RAR

295 CBR files, every one invisible. §2.1 excluded them because "it is RAR, which nothing in the stack reads" — and that had quietly stopped being true: macOS ships /usr/bin/bsdtar, which is libarchive, and libarchive reads RAR. No new dependency, nothing to install, nothing proprietary.

A comic packed with RAR is packed again as a zip on the way out

§6.9 already does this for an unpacked EPUB directory, and the reader, the positions and the highlights carry on knowing nothing about it. A 3.5 MB comic is repacked and served in 23 ms.

Listing is cheap and extracting is not

-tv reads headers and decompresses nothing, so a cover asks for one entry, not for the archive — the largest comic here is 315 MB, and holding all of it to make a thumbnail is not a trade worth making. Reading all 295 for metadata takes 4 seconds.

Extracting to stdout, never to disk

No temporary directory, no permissions, no path that might climb out of one. -tv gives every entry's size in archive order and -xO gives every entry's bytes in the same order, so the stream splits exactly — checked byte for byte against a 315 MB comic. If the two ever disagree the split is a guess, so it is refused rather than handing a reader half of one page stuck to half of the next.

libarchive reads most RAR, not all

10 of 205 are refused with "Prefix found: Inappropriate file type or format", all ten one run of 2003-vintage Marvel Premiere archives. A book that cannot be unpacked is reported and skipped like any other unreadable file; it does not take a scan down.

It reads RAR and cannot write it, and nor can anything else here, so there is no RarBuilder beside EpubBuilder and CbzBuilder and there cannot be. The process is the injected boundary: the tests fake what bsdtar writes, so what they cover is our reading of it — the listing parser and the size split, which is where a bug would live.

Measured: 295 files, 205 distinct comics. The other 90 are byte-identical copies filed in two places, folded into one book without being asked. 195 are on the shelves and 10 carry their error. Comics went from 286 to 481, the library from 2,176 books to 2,381.

What the file is, never what it is called

Some .cbr files here are zips, and §2.1 recorded .cbz files that were RAR. Both are read by sniffing the magic, so neither is a special case any more — the error message that existed to explain the mismatch is gone, because there is nothing left to explain.

A count that disagrees with its own list, again

The Comics group said 491 and the shelf showed 481: the ten unreadable archives have a book row and no metadata, so anything counting rows counts them and every list joins metadata and cannot. §6.8 settled this for the status line; the format counts now join through as well.

6.13  A scan notices a deletion; it does not act on one

A vanished book is marked missing_since and kept — §5 says it in as many words, "vanished; row never auto-deleted". That is why it leaves the shelves at once while your place in it survives, and it is what makes an unplugged drive a nuisance rather than a disaster. It is the wrong answer for a book deleted on purpose, so ./run.sh forget is a separate act, and it says what would be lost before losing it.

Rule

A whole library that has vanished has not been deleted. It is on a disk that is not mounted, and forgetting it would throw away every highlight and reading position in one go. Above half the library missing, this refuses and says why.

6.14  Some files simply lie

Star Wars - Refugee carries Dave Taylor as its dc:creator; the book is by Sean Williams and Shane Dix. Nothing automatic reaches that — the file is not damaged, the title is not a filename, and two confidently wrong names look exactly like one author who needs merging, which is how they surfaced. PUT /api/books/{id}/authors lets a reader say who wrote it, and what they say is kept as theirs and locked, because the file will go on saying Dave Taylor for ever.

6.5  Asking a provider 1,200 times

A library-wide title run asks Open Library about 400 authors, three requests each. Sent flat out that earns 503, Connection reset by peer, and SSL handshake timeouts — all three, in one run.

Open Library publishes its limits: 1 request/second anonymously, 3/second for a client that identifies itself with an application name and contact address — which OPENLIBRARY_CONTACT_EMAIL provides. PROVIDER_MAX_RPS sets the pace, defaults to 2 for headroom, and is capped at their ceiling. Their APIs are explicitly not a bulk backend — for bulk work they ask you to use the monthly data dumps, which is a fair description of a 1,300-book sweep, and the reason every answer is cached.

PoliteFetcher spaces requests out and retries what is worth retrying: 429, 5xx, and connection failures, but never a 404, which is an answer. It wraps the fetcher rather than the providers, so the providers stay ignorant of it, and one instance is shared by the whole service — four providers each pacing themselves is four unsynchronised streams.

Retrying is right for a hiccup and wrong for an outage

Open Library went down twice during this work, and each new author then cost four attempts and 48 seconds of backoff before being abandoned — nearly three hours for the ~200 authors the MOBI books brought in. After four whole failures in a row a host is treated as down and calls fail at once: the same run took two and a half minutes. Judged per host, and an HTTP error does not count — a 404 is an answer, and a host that answers is not down. One success clears it, and so does five minutes.

The suite now injects a fetcher that refuses immediately, so no test touches the network. One endpoint test had been making real requests all along; it took 48 seconds on the day Open Library was struggling.

07Sorting

Sort keys are computed once at ingest and stored as indexed columns, so browsing is a plain ORDER BY and stays fast at 10k+ books. No string mangling at render time.

  • title_sort — lowercased, leading article stripped (locale-aware: The/A/An, De/Het/Een, Le/La/Les), NFKD, diacritics folded
  • author.sort_name — Last, First, particles handled (Le Guin, van der Meer, de Beauvoir), suffixes kept out of sort position
  • series_index is REAL, so 2.5 sorts between 2 and 3; unnumbered entries sort last
  • Years browse uses first_published, never edition_date — a 2019 printing of a 1969 novel belongs in the sixties

8.2  Covers: page one, when page one is the cover

555 books of 2,179 showed a lettered tile, and 514 of them were PDFs — every PDF in the library. M7 skipped this because rasterising a page was a heavy dependency for a proof-of-concept; at 514 blank books that reasoning expired. pdfium is BSD, ships as a wheel with the binary in it, and needs no network.

The question is not "is this a scan?" but "is page one a cover?"

A cover is one raster image covering the page with no text over it; a title page is text. That rule keeps the text-born books whose first page is a proper cover image, and it asks what page one is rather than what the file is. Measured first: of 514 PDFs, 34% open on a full-page image and 61% are text-born — so this was always going to close part of the gap, not all of it.

Apply, then audit — and the audit was the point. 159 books took a cover; all 159 were rendered as contact sheets and looked at. 145 were genuine cover art and 14 were not: twelve academic title pages (Routledge's, with "Also available as a printed book" across the foot), Neil Gaiman's A Study in Emerald, which is a facsimile Victorian newspaper page, and a page of Calvin and Hobbes strips. 91% right, and the 9% could only be seen.

A wrong cover is worse than no cover, so saying so is a feature

DELETE /api/books/{id}/cover drops the picture and records origin = 'user' on the cover field — the same rule as a corrected author, so no later pass fetches another. The 14 went through that endpoint rather than a script.

A pixel rule was tried and rejected: pale-and-grey would have dropped 16 title pages, but also Stephen King's On Writing, whose real cover is white with handwriting on it. Nothing separates a white cover from a white title page except looking, so the code does not pretend otherwise.

8.3  Covers: asking a provider for the rest

396 books were still showing a letter — text-born PDFs whose first page is a title page, plus EPUBs and PRCs whose files carry no image at all. Their own files have nothing left to give.

Measured before building it, on 40 random cover-less books: 70% get an offer from Open Library, and about three in four of those offers are the right book. A dry run over 20 more matched 12. So this closes over half of what is left — and gets some wrong, which shapes the design.

The enrichment score is the wrong instrument here

It refuses to redistribute weight over fields we do not have, and these books have no ISBN, no year and mostly no author — so a correct match scores 0.19. CoverMatch asks the only question a picture needs: do the titles agree once the filename scaffolding is off both of them. Vampire Files 02 - Lifeblood matches Lifeblood; Mute does not match God on Mute.

249 of these books name their author in the filename and nowhere else — the PDF reader takes the author from the Info dictionary only, so Anthony, Piers - Mute.pdf has none in the database. AuthorHint reads it back off the filename for matching: surname-first at the head is taken as written, and a name at the end counts only when the library already knows that surname, or "The Eagle and the Wolves" acquires a Mr Wolves. It is a hint and nothing more, never written to the database.

Asked once, ever — and on its own, much slower clock

A miss is recorded exactly like a hit, so the next run does not ask again; a lookup that failed is not recorded, so an outage costs nothing but time. And a sweep of 400 lookups in one sitting is closer to bulk than to browsing, which Open Library asks people to do from the data dumps — so COVER_FETCH_INTERVAL (default 60 seconds) paces the search API alone, while the pictures, static files on another host, keep the ordinary pace. An overnight job rather than a ten-minute one, resumable at any point.

Open Library answers a cover it does not have with a one-pixel image rather than a 404, so anything under 100 px is refused and recorded as a miss.

Measured over the whole library: 396 asked, 210 covers, 53% — which with the pdfium pass took the library from 1,624 covers to 1,978 of 2,179, or 90%.

The audit found 15 wrong in 210 — 93% right. Two were the wrong book: Hadrian's Wall (ours is Osprey's; the cover is a 1922 book of the same name) and Star Wars: Edge of Victory I — Conquest, which matched Jude Deveraux's The Conquest because stripping the scaffolding left the word conquest and nothing else. The other thirteen were the right book wearing the wrong picture — title pages, two blank Oz placeholders with the title typed on them, and a maroon library binding with a barcode.

An author is corroboration, not a veto

The library holds The Art of War by Sunzi; Open Library files it under Sun Tzu. Both are that man, and refusing on the spelling cost a cover for nothing. The author now ranks answers rather than vetoing them — agreement beats disagreement, and the best is taken rather than the first — while a title-only match is recorded as openlibrary-title, so an audit can look hardest at the ones that were least sure. The title stays the guard: Mute still does not match God on Mute.

Rule

A security test that passes for the wrong reason is worse than none. Tests asserting that a protection holds are verified by temporarily breaking the protection and confirming the test fails. Done for the CSP containment test in M0.

Rules earned the hard way

Browsers

The UI suite runs against Chromium and WebKit. This is read in Safari on a Mac, an iPhone and an iPad, and foliate-js is developed against WebKitGTK. Chromium-only testing is how a total failure — books never opening in Safari — shipped unnoticed with a green suite.

Test isolation

The UI suite runs serially. One server, one database, and reading position shared across devices by design means parallel tests race over real application state. And a position test needs a book no other test opens — opening a book writes a position, so avoiding the assertion is not enough.

Evidence

Assert the thing, not its proxy. A test that checked the cover element existed passed for as long as the cover was invisible in Safari; the test that mattered samples the image's actual pixels. The CSP containment test is likewise verified by breaking the policy and watching it fail.

Matching: scored by evidence

Most EPUBs have no ISBN, so matching is fuzzy against providers that confidently return the wrong edition. Two flaws the tests caught before any of it ran:

  • Weights must not be redistributed over the fields we happen to know — that made a title-only match score 1.0 and auto-apply, which is precisely the case that returns the wrong edition. An unknown field contributes nothing, so a thin match scores thinly.
  • A conflicting ISBN is evidence, not noise to ignore: the score is discounted enough to keep it out of auto-apply while still allowing review.

Calibrated on the real library. A first run over 18 random books returned no candidates at all for 33% of them — every one had filename scaffolding in its title (Elliott, Kate - Crown Of Stars 01 - King's Dragon). What we send a provider is therefore not what we compare against: search_title() strips author, series and list-number prefixes. No-candidates fell from 33% to 22%, auto-apply rose from 38% to 44%.

Author enrichment

Open Library fills About the author and Also published. The fetcher is injected, so no test touches the network and a cache or rate limiter can wrap it later without touching the provider.

  • A near-miss is never guessed at. An author matches only when the folded sort names are identical — the wrong author's bibliography is worse than none.
  • A hand-written bio is never overwritten. bio_source = 'user' survives every re-run: the provenance rule doing its job.
  • Failure is reported, never raised. An unreachable provider returns matched: false with the reason on screen.

What a real bibliography looks like (Le Guin, live): 200 works returned, 22 of them duplicate titles, and bind-ups listed as slash-joined titles. After collapsing duplicates and treating those as omnibuses: 178 works, 141 novels. Translations remain — the works list carries no language — which is M5's problem rather than a defect here.

TLS

Certificate paths are configuration, not a guess. Indexing

epub_index.py answers one question on every start: what appeared, changed or vanished? The earlier JSON-manifest scanner has been deleted — the book table tracks the same facts and more.

  • Recursive, because 44% of the real library lives in subfolders.
  • Incremental by size + mtime: unchanged books are never re-hashed. Measured on the real library — 1,326 books in 7.7 s cold, 0.3 s warm, hashing 2 files.
  • Identity is the content hash: the same book filed twice is one row, a moved file updates its path, and an edited file updates in place rather than orphaning the old row.
  • Every per-book failure is caught and recorded against the book. A corrupt EPUB must never stop a run.
  • A new FTS table does not backfill itself — after the search migration every book was "unchanged", so the indexer catches up any book with metadata and no search row.

What M1 established

  • Position is keyed by content hash, not filename. Renaming a book keeps your place, and there is a test for exactly that. M2 introduces book.id and can add the foreign key.
  • Position is server-side and shared; display settings are per device. Where you are in a book is a fact about the book. How large you want the type is a fact about the screen you are reading on, so it lives in localStorage — and the UI says so.
  • Saves are debounced (800 ms) because relocate fires on every page turn, and flushed on pagehide so closing a tab mid-chapter loses nothing.
  • A stale CFI must never strand the reader. ReaderEngine.open() falls back to the first page if goTo(cfi) throws — a book replaced on disk would otherwise open blank.
  • foliate REPLACES the book iframe when changing section. A Frame reference captured before navigating goes stale. tests/frontend/helpers.js re-resolves it on every poll.
  • Reopening a finished book does not un-finish it. The upsert preserves finished/abandoned; only an explicit status change clears it.

A linter, and the 116 things it found

This project had none. Running ruff cold on a finished codebase found 116 findings and no bugs — the point twice over: none of it was wrong, and nothing had been checking. The tell was eleven unused # noqa comments, suppressions written for a linter that had never existed.

One finding was a bug waiting to happen

epub_index rebound image inside its own with, so the RGB conversion was assigned and thrown away — a cover with an alpha channel could never have been saved as JPEG. Renaming the loop variables in epub_genres and epub_pdf the same way would silently have dropped a .strip() in each; caught by reading what the rest of the block still used, which is the whole risk of a mechanical tidy-up.

Rules are chosen rather than defaulted, at ruff's own line length of 88 — asking for 79 flagged 436 lines, almost all in tests. RUF001–003 are off because the prose here uses en-dashes on purpose. Two false positives are suppressed with the reason: sqlite3.Row has no __contains__, and ScannerTags.strip is not str.strip. And it is enforced rather than hoped for — tests/test_lint.py runs ruff and fails on anything, because a tidy-up nobody enforces lasts until the next commit.

A method that was 56% of its module

EpubGateway._register_routes was 530 lines holding 57 nested functions — more than half of a 945-line file, and the largest thing in the codebase was not a class at all. No route could be tested without standing up the whole app.

Five classes now, grouped by what they are about rather than by what FastAPI needs: the app itself, browse, shelves, reading, and the maintenance passes. epub_server.py went from 945 lines to 398.

Reaching into another object's privates only moves the problem

The routes needed nineteen of the gateway's attributes, and a route class saying gateway._browse would be the same coupling spread over more files. Services is those collaborators, named and public, handed over once.

A regex does not know a string from an identifier

Rewriting shelves → self.services.shelves over the source text rewrote it inside "/api/shelves" too, and four URLs quietly moved. The rewrite is done over tokens now, editing by position so spacing, comments and docstrings survive exactly. And ast.get_source_segment does not include decorators, so a first pass moved 51 route bodies and left every @app.get behind — everything answered 404, /healthz included, which is how it was caught immediately rather than subtly.

One place for the rule everything depends on

§5's provenance rule is the invariant the whole design rests on — and it was written eleven times. Every pass hand-rolled its own INSERT INTO field_provenance … ON CONFLICT, and eight carried their own copy of the guard that reads it back.

A rule that must be copied into N places will eventually be in N−1

Not a tidiness complaint: a rule added one afternoon — a title a provider confirmed outranks one derived from a filename — went into three of those eight by hand, and the pass it was missing from spent a scan undoing the other two's work.

Provenance writes it and Candidates reads it. The guard exists twice on purpose — a method for one book, a SQL clause for a pass selecting thousands — because asking per book would mean one query per candidate. Two forms of one rule is exactly how they come to disagree, so a test drives both over every combination of origin, source and lock and asserts they never do.

Two guards were deliberately left alone, being different questions in the same shape: ProviderCovers asks "have we already been here?" rather than "may I write?", and TitleFromWorks refuses any title a provider has set, because asking a bibliography about a book somebody has already answered for is a request spent on nothing. Saying so in a comment is the point — an exception nobody wrote down is indistinguishable from an oversight.

11Conventions

  • Match dlna-gateway: vanilla JS, no framework, no build step, one app.css with :root tokens, one app.js
  • Palette and type inherit dlna-gateway's tokens (--bg:#0A1526, --amber:#FFC24A, Syne + DM Mono) so the two apps read as a family — except inside the reader, where the book's page gets a neutral reading theme and the app chrome gets out of the way
  • foliate-js is a pinned submodule, never edited in place; differences go in reader.js
  • All SQLite access server-side; the frontend only sees JSON
  • Migrations forward-only and numbered
  • Track current SQLite, and use it. Database.NEEDS is checked on the way in and says what to do if it is not met. Writing round old versions costs clarity for nothing — the workaround is always less obvious than the feature, which is how GROUP_CONCAT's ordering came to be silently wrong (§6.11c). This supersedes the older "the same on any SQLite" rule; the COALESCE it produced still works and is left alone.
  • Intl.Collator / Intl.Segmenter over hand-rolled string logic — the library is multilingual
  • Never modify the user's book files — read-only, always
  • Every user-facing string is written from the reader's point of view, not the system's

12Open actions

Measured against the real library on 19 August 2026. What is done is listed first and briefly — the reasoning behind each lives in §6 and §8, where it belongs. What follows it is genuinely unfinished, left exactly as it was written. What closes the section is not a to-do list at all: those are limits that were weighed and accepted.

Done

  • Cover art. From the book's own first page where that page is a cover, and from a provider for the rest. 91% of books carry one.
  • A co-author written into the title is read as a second author, by a rule that costs nothing.
  • A title cut off by a filesystem is finished by asking a provider for the trimmed form, and only accepted when the answer completes what we hold.
  • A filename read as three facts — author, series and title — across the library, each run aimed at one author and read before it was applied.
  • What the scanner wrote into the title — version stamps, not ocr, underscores standing in for spaces — taken off by a closed vocabulary.
  • Comics packed with RAR read and served, bringing in several hundred books that had been invisible.
  • Browsing by format, grouped as a reader thinks of them rather than as the disk stores them.
  • A scan reads what it finds. The passes that cost nothing run on every start, so dropping a book in and restarting is the whole workflow.
  • Duplicate copies folded to one row per work, audited each time and reversible; no file was ever deleted.
  • A linter, a single place for the provenance rule, and the routes split into classes — the three findings of a review, taken in order.

Still open

1 — The names that are clear to a person and not to the code

This is the next piece of work. Piers Anthony's filenames were obvious to a reader and opaque to the code, and closing that gap is the job. It is deliberately not a general enrichment sweep: Dune - Frank Herbert needs nothing from anybody, and asking about it would be an afternoon spent confirming what we already hold.

The gate comes first, and most books never pass it

A name goes to a provider only when nothing here can already read it. Three kinds of certainty, all local and all free: one side of the name is an author we already hold (573 of them); the shape is one §6.11b already reads; or the file's own metadata agrees with its name. Only what survives all three is asked about.

The filename stops being the answer and becomes a hypothesis

§6.11b believes one rigid shape outright, which is why it needs a comma at the head, why it fires on 241 books and no others, and why 10 is Better Than 01 - Heather Jarman had to be refused rather than understood. The new pass cuts a name every plausible way, asks Open Library which reading is real, and keeps the one that comes back corroborated.

  1. Split into candidates, not into an answer — both orderings, every separator, with and without a leading number.
  2. Anchor on whichever end confirms. Ask whether the candidate author exists, or whether the candidate title does. A name where neither end confirms is left alone and said so.
  3. Find the other end through the anchor — a known author's works, never a global title search. "Second Chance" matches hundreds of books; this author's Second Chance is one question with one answer.
  4. Score into the bands that already exist — decision 4's ≥0.90 / 0.60–0.90 and the review queue, which already stores why it scored that and which fields would change. A second queue would only disagree with the first.
Here a provider's answer wins, because nothing else is offering

Everywhere else the file leads and enrichment fills silence. The gate has already established that neither the file nor its name can be read, so a confirmed reading is the only evidence in the room. That also settles title: outside the enrichment writable set for every book whose name we can read, writable for the ones we cannot.

Every question asked is written down, hits and misses alike

Several hypotheses per book is where "asked once, ever" stops being enough: author.fetched_at records that we asked about a person, and this asks about a string. It needs a query → answer cache keyed on the question, or the second run costs what the first did.

Measure before building it, as the cover work did twice: 30 real unreadable filenames through the splitter, counting how many anchor at all. If the answer is 20% this is a different piece of work, and better to know that on the first morning.

2 — Names that are damaged: the open web

Tiers 0 and 1 are built — a co-author freed from a title (§6.11c), and a truncated title finished by trimming it back to a whole word and asking a provider (§6.11d). Tier 2 is not, and the gate on it still holds: a catalogue can only match what it holds, while a search engine indexes the long tail. It needs a real search API, never scraping, reads result titles and snippets only, applies tier 1's prefix rule plus the author appearing in the same result, and requires two independent results to agree before writing anything. One query per string, ever.

Do not build it until the free tiers have been measured against what is left. They were, and they left very little: the population tier 2 could reach is now a handful of books, and it is the only part of this that costs money.

3 — Fetch each matched work's own record

Open Library's search results carry no synopsis and no publisher, so auto-apply writes almost nothing: of 2,364 books shown, 2,097 have no synopsis, 2,058 no genre and 1,769 no first-published year. One extra request per book fixes all three — and it is the same call that confirms a candidate above, so they are one piece of work rather than two.

4 — Editing a book's metadata

Series is not coming from a provider. §6 said it would and it was never built; Open Library's search results are thin enough that its series data is unproven, and nothing measured here says it can tell Xanth #8 from Xanth #9. The answer is the reader's own hand. Hand-editing today is authors and series only; it should be the whole record — title, series and number, synopsis, genre — because that is the only thing that reaches a book the machinery cannot: the truncated Bamboo Bloodbath & Ninj, the clipped The Caterpillars Questi, a series nobody else has heard of. It costs no requests, and the machinery exists already: what a person says is origin = 'user', locked, and no pass overrules it.

1,434 books have no series. Filenames gave what they could and hand-filing reached the rest that could be proved; most of what is left either genuinely stands alone or needs a person.

Constraints the builder accepted

Not a to-do list. Each of these was weighed, and the cost of removing it judged higher than the cost of keeping it. They are written down so that a later reader can tell a decision from an oversight.

  • Hand-editing is authors and series only. Title, synopsis and genres stay provider-or-file, because the file's title is what you see in your own folders. §12's editor would change this deliberately.
  • 9% of books have no cover. Their own files hold no image and no provider matched them. A wrong cover is worse than none, so the lettered tile stays.
  • 57% genre-map coverage. The rest is genuine junk — Rand al'Thor (Fictitious character) — logged and never guessed.
  • Ten comics cannot be opened. libarchive refuses one run of 2003-vintage RAR archives. Another unrar would reach them, at the cost of a dependency that is not already on the machine.
  • foliate-js is pinned at 78914ae and has never been updated, while upstream declares itself unstable. Updating is a deliberate act with the whole UI suite behind it.
  • No Calibre interaction of any kind, no format conversion, no device sync, no DRM. Each is a product of its own.
  • The test database accumulates between runs, so uniquely-named shelves pile up. Harmless until a test counts globally, which one did.
