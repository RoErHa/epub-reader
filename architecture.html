epub-reader architecture

One FastAPI service on :8770, a vanilla static front end, and a SQLite index over books that never move. This page describes the code as it is — every number on it was measured from the source and the live database, not from the plan.

01The shape of it

Three things carry the whole design, and each one closes off a category of problem rather than solving an instance of it.

Files stay put

Books are indexed in place and never moved, renamed or written to. Identity is the content hash, so moving a file updates a row instead of creating a second book.

Every field remembers its source

field_provenance records whether a value came from the file, a provider or a person, and whether it is locked. That is what makes re-running a pass over the whole library safe.

The engine is a dependency

foliate-js is pinned at 78914ae and imported by exactly one file. Rendering, pagination and CFIs are not ours to write.

What is left after those three is the part worth building: the index, the browse UI, and the metadata repair that turns thirty years of other people's filing into something a reader can search.

Amber marks a module four or more others depend on. Fan-in of 0 means nothing imports it: epub_gateway is the entry point, and epub_genres is loaded by data rather than by import.

The graph is acyclic and shallow — seven layers over 39 modules, with the widest layer holding ten. Nothing in layers 0–2 knows that an HTTP server exists, which is why the passes can be driven equally from run.sh and from a route.

03Two foundations

Twenty of the 39 modules import epub_names, and eleven import epub_provenance. Nothing else comes close. Both are small — 122 and 117 lines — and that is the point: they hold a rule rather than a subsystem.

A name is normalised in one place or in none.

PersonName and title_sort_key decide what Le Guin, Ursula K. sorts as, what counts as one word when an apostrophe joins two, and when an underscore is standing in for a space. Every pass that reads a filename asks the same question of the same code, because two implementations of one judgement is exactly how they come to disagree.

The provenance rule was written eleven times before it was written once.

Every pass hand-rolled its own INSERT INTO field_provenance … ON CONFLICT, and eight carried their own copy of the guard that reads it back. A rule that must be copied into N places will eventually be in N−1 — and it was, which cost a scan spent undoing its own work. Provenance writes it, Candidates reads it.

The guard exists twice on purpose: as a method for one book, and as a SQL clause for a pass selecting thousands, because a pass that asked per book would run one query per candidate. A test drives both over every combination of origin, source and lock and asserts they never disagree.

04The composition root

epub_server imports 28 modules and is imported by one. It is where everything is wired together and the only place that knows the whole system exists. It is also 398 lines, because it composes rather than does.

That took a deliberate cut. EpubGateway._register_routes was once 530 lines holding 57 nested functions — more than half of a 945-line file, and the largest thing in the codebase was not a class at all. The routes are five classes now, grouped by what they are about rather than by what FastAPI needs.

Route classRoutesAnswers for
AppRoutes4health, the shell, status, cover images
BrowseRoutes14authors, series, genres, formats, years, letters, search, detail
ShelfRoutes9stored shelves, smart shelves, membership
ReadingRoutes8position, status, annotations, the book's bytes
MaintenanceRoutes17the repair passes, the review queue, hand-editing
Reaching into another object's privates only moves the problem.

The routes needed nineteen of the gateway's attributes, and a route class saying gateway._browse would be the same coupling spread over more files. Services is those collaborators — 21 of them plus the two identity strings the health check reports — named, public, and handed over once.

05Three request paths

Everything the browser asks for takes one of three routes through the service, and they differ in what they are allowed to touch.

Browse · read-only JSON

app.js → /api/* → BrowseQueries → SQLite

Sort keys are computed at ingest and stored as indexed columns, so browsing is a plain ORDER BY. Every listing joins through to a present book, which is why the status line cannot disagree with the shelf below it.

The book itself · bytes

reader.js → /api/books/{id}/file → disk

Addressed by id, never by path — 44% of a real library lives in subfolders. A RAR comic is repacked as a zip and an unpacked directory is zipped, both on the way out, so the reader, the positions and the highlights know nothing about either.

Maintenance · writes, with provenance

run.sh or POST → a pass → Provenance

Dry-run by default, database-only, and no file is ever renamed or written. What a pass changes it records, or the next scan would undo it.

06Load-bearing boundaries

Four rules are structural rather than stylistic. Each one exists because breaking it has already cost something.

BoundaryEnforced byBecause
static/reader.js the only importer of foliate-js upstream declares itself unstable at version: 0.0.0; churn lands in one file
epub_config.py the only reader of .env one configuration source, so a TLS path is configuration rather than a guess
epub_provenance.py the only writer of field_provenance the rule the whole design rests on, in one place instead of eleven
epub_security.py a CSP on every response EPUBs can carry JavaScript, and iframe sandboxing cannot contain it

What the policy actually allows

DirectiveValueWhy not tighter
script-src'self'a hostile EPUB's inline and external scripts both refuse to run — verified by breaking it and watching the test fail
style-src'self' 'unsafe-inline' blob:foliate serves every resource as a blob: URL; without it each book loses its own typography
frame-ancestors'self'WebKit propagates the page's policy into blob: documents, so 'none' made every book refuse to load its own frame
connect-src'self'nothing in a book may call home

A security test that passes for the wrong reason is worse than none. The containment test is verified by temporarily weakening script-src to allow 'unsafe-inline' blob: and confirming it then fails — so it is not passing vacuously.

08Where it strains

Written down so a later reader can tell a decision from an oversight.

StrainStateCost of removing it
foliate-js pinned at 78914ae, never updated, upstream unstable accepted a deliberate update with the whole UI suite behind it
epub_index at 557 lines and epub_gateway at 507 the two over the ~400 the review asked for another split; everything else already fits
Ten 2003-vintage RAR comics libarchive refuses reported, skipped a second unrar that is not already on the machine
9% of books carry no cover lettered tile nothing — a wrong cover is worse than none
57% genre-map coverage by design guessing at wierook32, which the map refuses to do
Series from a provider never built unproven data; hand-filing answers it today

The test suites are the check on all of it: 1,174 pytest over 12,165 lines, and 428 Playwright over 15 specs, run serially against Chromium and WebKit because position is shared server-side by design and Safari is the browser this is actually read in.
